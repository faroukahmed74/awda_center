1. Why clinics buy Clinic OS

ليه العيادة تشتري النظام؟

نظام عام لأي عيادة: بدل الدفتر وواتساب والإكسل — استقبال، أطباء، متدربين، مرضى، ومالية بالجنيه، عربي وإنجليزي.

Clinic OS is not a “booking widget.” It is the daily operating system of a physical-therapy clinic: who is in which room, who supervised vs who performed the session, what package remains, what was paid in EGP, and what the owner sees at month-end.

For the owner / admin

  • Live dashboard: income, expenses, net, workload by doctor & trainee
  • Finance summary with clinic economics (targets, slices, MANG / BASKET)
  • Audit trail of who changed what, on which platform
  • Role & privilege control down to chat media types

For reception & floor staff

  • Day schedule by rooms · conflict prevention
  • Statuses that match real life: apologized / absent with or without cause
  • Packages, services, price quote at the front desk
  • Create patients without forcing them through self-registration only

For doctors & trainees

  • Own schedule or clinic-wide (by privilege)
  • Rich medical notes, VAS, progress, documents
  • Performing-doctor credit without breaking billing
  • In-app clinic chat with media

For patients

  • Same app: book, view appointments, profile
  • Price quote for services & packages
  • Push / reminder awareness (mobile)
  • Arabic or English UI

3. Roles, privileges & security

الأدوار والصلاحيات والأمان

Built-in roles

RoleTypical access
AdminEverything: dashboard, users, finance, audit, chat oversight, settings
SupervisorNear-admin operations; can book past dates (migration); audit read
SecretaryUsers, appointments, reports, chat defaults (view-all / manage group)
DoctorAppointments, patients, reports, own doctor profile, chat
TraineeChat by default; appointments/patients via grants; can be performing doctor
PatientMy appointments, profile, book, price quote, chat

Privilege model (sales differentiator)

  • Multi-role users (e.g. admin + doctor) via roles array.
  • Per-user permission overrides — admin edits privileges without redeploying.
  • Fine-grained clinic keys: admin dashboard, appointments see-all / view-all, patients edit, income, finance summary, reports, requirements, admin todos.
  • Fine-grained chat keys: start chats, message anyone, send text/image/video/audio/voice/document, save media, broadcast, create/manage groups, retention, delete own / delete any, chat settings.

Security posture (honest positioning)

  • Firebase Authentication (email/password, Google); inactive accounts blocked.
  • Firestore & Storage security rules gated by role helpers + permission checks.
  • Staff can create patient Auth accounts via secure Cloud Functions (not “open signup only”).
  • Immutable audit log (create-only; admin/supervisor read).
  • Position as: role-gated cloud clinic system with audit & Firebase rules — not a certified EMR/HIPAA claim unless separately certified.

4. Appointments & schedule (core floor ops)

المواعيد وجدول العيادة

جدول يومي بالغرف، منع التعارض، حالات اعتذار/غياب حقيقية، باقات، وفلاتر للمشرف والقائم بالجلسة.

Views

  • List view with status chips, date navigation (day / month / year), search.
  • Schedule (day) view: time slots every 30 minutes (00:00–23:30), rooms as columns, sticky-friendly layout for reception desks.

Create / edit appointment fields

  • Patient, supervising Doctor, optional Performing doctor (doctor or trainee)
  • Room, date, start/end time, multiple services, linked package
  • Cost, discount %, notes, optional extra slot, VIP star

Statuses that match Egyptian clinic language

  • Pending · Confirmed · Attended (completed) · Cancelled
  • Absent · Apologized (absent with cause) · Absent without cause / no-show
  • Cancelled / absent / no-show do not keep occupying the room slot

Slot & conflict rules

  • Up to 3 main + 1 extra appointments per time slot / day logic used by the clinic.
  • Room overlap blocked so two sessions cannot claim the same room at overlapping times.

Filters & payment on complete

  • Filter by service, package, supervising doctor, performing doctor, status, search (patient / doctor / performer / service).
  • On complete: paid / partial / prepaid / not paid — can create linked income entry.
  • Dashboard “today’s appointments” shows supervisor / performer when they differ.

Who sees what

  • Doctors default to their own book; privileges unlock clinic-wide see-all / view-all.
  • Admin / supervisor can book past dates for data migration.
  • Patients self-book via dedicated booking dialog.

5. Performing doctor & session workload

الدكتور القائم بالجلسة وجهد الجلسات

Built for training clinics and busy floors where the billing doctor is not always the person who ran the session.

  • doctorId = supervising / billing doctor (income stays here).
  • performingDoctorId = who actually performed (doctor doc id or trainee user id) — stats only.
  • Admin dashboard Session workload table + chart: counts as supervisor, as performer, and total.
  • When supervisor ≠ performer, both get credit (dual count). Legacy sessions without a performer stay “as performer = 0”.
  • Visible on appointments list, dashboard, patient detail, and admin reports — never silently changes money.

6. Patients & medical records

المرضى والسجل الطبي

Patient management

  • Searchable list (cached), deep-link search query support.
  • Staff creates patients via Cloud Function (email account + profile) — front desk friendly.
  • Patient code for clinic IDs; login with email or patient code.
  • Secondary phone, AR/EN display names.
  • VIP / starred patient flag for priority clients.

Medical profile (deep)

  • Demographics: DOB or age, gender, address, occupation, referred by, marital status, areas to treat, fees type, followed-by doctor.
  • Clinical: chief complaint, diagnosis, medical history, treatment goals/plan, progress notes, pain (VAS), contraindications, previous PT/surgery, treatment progress.
  • Rich text (Quill): bold, underline, size, color; Delta JSON (HTML/plain fallback); per-field label colors.
  • Session notes: VAS, ROM, function, progress, free notes.

Documents & patient PDF report

  • Upload/view: ray, lab, report, image, PDF, note — images fullscreen; PDF via viewer.
  • Patient report PDF: personal + medical + sessions (+ weekday on dates) + payments + packages; Arabic fonts + reshaper; chunked tables for large histories (stable on mobile).

7. Services, packages & price quote

الخدمات والباقات وعرض الأسعار

  • Services catalog: AR/EN names, amount per session, used in booking.
  • Packages: AR/EN name & description, linked services, session count, fixed amount, active flag.
  • Appointments link to packageId; package progress tracked in patient admin screens.
  • Price Quote screen (available broadly): public-facing list of active services & packages for front-desk quoting without opening finance.

8. Income, expenses & finance summary

الدخل والمصروفات والملخص المالي

Income & expenses

  • Default currency EGP.
  • Income: amount, source, date/time (can preserve session time), notes, doctor/patient, appointment link, payment status; add/edit/delete; search; day/month/year summaries.
  • Expense categories: Salary, Rent, Supplies, Media, Other (+ recipient for salary, paid-by-doctor).
  • Category mapping into finance summary buckets (e.g. Salary→Receptionist, Rent→Rent+Guard, Media→Media).

Finance summary (owner P&L style)

  • Per-doctor income, 30% target, bonus, slice-based commission table, consumables, media.
  • Shared lines: Rent+Guard, Receptionist.
  • Outputs familiar to partner clinics: NET, MANG, BASKET, profit; reorder doctor rows; config saved per month.
  • Periods: month / quarter / 6 months / year.
  • Bilingual PDF with Amiri + Arabic reshaper; download/share on all primary platforms.

نظام تشغيل عيادة علاج طبيعي متكامل — قابل للعلامة التجارية باسم عيادتكم

النظام تطبيق واحد (ويب + أندرويد + آيفون) يدير العيادة يوميًا بدل الدفتر وواتساب والإكسل: مواعيد وغرف، سجل طبي غني، باقات وجلسات، دخل ومصروفات بالجنيه، ملخص مالي للشركاء، شات داخلي، إشعارات وتذكير، لوحة إحصائيات، وصلاحيات دقيقة لكل دور.
